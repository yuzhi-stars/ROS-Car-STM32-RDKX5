# 固件结构与工作流程

本工程为裸机主循环＋定时中断架构，没有运行 RTOS。时间要求较强的电机控制放在 TIM13，协议解析、姿态和显示等放在后台。学习时可先沿 `main.c` → `drive_control.c` → `Motor.c` → `rdk_uart.c` 阅读。

## 1. 模块职责

| 文件 | 主要职责 |
|---|---|
| `main.c` | 时钟/外设初始化、开机校准、主循环任务调度、HAL 回调转发 |
| `drive_control.c/.h` | 唯一的驱动来源仲裁：HOST/REMOTE/STOP，解锁、失联和目标提交 |
| `Motor.c/.h` | PWM、硬件编码器、实际时间间隔测速、轮速低通、四轮增量 PID |
| `Mecanum.c/.h` | 手动控制量到四轮目标的纯计算与限幅，保留当前轮序 |
| `Odom.c/.h` | 编码器计数积分的底盘位姿和速度快照 |
| `rdk_uart.c/.h` | RDK 二进制收发、CRC、指令检查、速度单位换算、反馈打包 |
| `uart_dma_rx.c/.h` | 循环 DMA、位置/接收时间事件、后台读取、错误恢复和溢出处理 |
| `ELRS.c/.h` | CRSF 帧、16 通道解包、开关滤波和遥控快照 |
| `IMU.c/.h` | LSM6DSR/LIS3MDL 的 SPI 访问和新采样标志 |
| `imu_calibration.c/.h` | 仅使用合格静止窗口的可重试陀螺仪零偏校准 |
| `imu_attitude.c/.h` | 不依赖 HAL 的六轴 Mahony 四元数解算 |
| `runtime_clock.c/.h` | DWT 周期计数、实际 dt 和后台时间预算 |
| `OLED.c`、`Menu.c` | 帧缓冲、变化区域、32 列 DMA 分片、旋钮菜单和 IMU 诊断 |
| `Flash.c` | I2C FRAM 中的 PID 参数保存/加载 |
| `INA219.c`、`Peripheral.c`、`LedStrip.c` | 电源监测、蜂鸣器/指示灯、灯带 |

`AnglePID.c`、`VoiceNavigation.c` 还保留在源文件清单中，但主循环已不调用历史方形轨迹、角度测试、开环或语音驾驶分支。不能仅凭文件还存在，就认为这些逻辑正在控制电机。

## 2. 开机顺序

1. HAL、168 MHz 时钟树、GPIO/DMA/定时器/串口等基础初始化。
2. INA219、OLED、IMU 初始化；OLED 配置保持熄屏。
3. 约 3 秒静止校准尝试，收集新的陀螺仪和加速度观测。
4. 加载 FRAM PID 参数，初始化电机和编码器、PID、里程计及菜单。
5. 开启 20 ms 控制定时器，初始化 RDK/ELRS DMA 和控制仲裁。
6. 设置 `g_peripherals_initialized=1`，进入正常调度。

启动校准结束前还没有正常的 RDK 应用反馈；不要将前几秒无反馈当成串口损坏。若校准未通过，主循环在轮子静止、目标为零时继续尝试，不再靠长期阻塞等待。若传感器初始化失败，当前代码没有完整的自动重初始化流程，应先检查硬件和总线。

## 3. 后台主循环

主循环依次服务 ELRS 接收、控制权更新、RDK 接收，再按节拍进行 IMU、反馈、菜单和其他外设处理。

| 任务 | 设定节拍/触发 | 说明 |
|---|---|---|
| ELRS/RDK 后台解析 | 每次循环 | 每次调用有字节和时间预算，不在 ISR 解码 |
| IMU 读取和 Mahony | 约每 10 ms 检查 | 只使用传感器实际新数据；传感器配置为 104 Hz |
| 轮速＋IMU 串口反馈 | 每 20 ms 尝试一次 | 正常约 50 Hz；SPI/I2C 异常或后台慢会降低实际频率 |
| OLED STATUS/IMU 页面 | 每 100 ms 更新 | 10 Hz 内容刷新，实际 I2C 数据分片异步发送 |
| INA219 读取 | 每 200 ms 且 I2C 可用 | 与 OLED 共享总线 |
| PID 保存检查 | 每 1000 ms 且 I2C 可用 | 仅变化时写 FRAM |
| 用户 LED | 每 500 ms 翻转 | 完整亮灭周期约 1 秒 |

主循环没有一个固定的总周期。`500 us` 是一次串口解析调用在每个字节/整帧处理结束后检查的预算，不是所有任务累计时长的保证，更不是实测最坏 ISR 延迟。

## 4. 中断、DMA 与优先级

| 功能 | 硬件资源 | NVIC 优先级 |
|---|---|---:|
| 电机控制 | TIM13，共用 `TIM8_UP_TIM13_IRQn` | 1 |
| ELRS RX | UART5＋DMA1 Stream0/Channel4 | 2 |
| RDK RX/TX | USART3＋DMA1 Stream1、Stream3/Channel4 | 3 |
| OLED TX | I2C1＋DMA1 Stream6/Channel1 | 6 |
| 灯带 | TIM1＋DMA2 Stream2/Channel6 | 7 |
| 1 ms 系统时基 | SysTick | 15 |

数字越小，抢占优先级越高；完整配置还包括 GPIO 等中断，应以 `gpio.c`、`dma.c`、`usart.c` 为准。DMA 的硬件仲裁优先级是另一个设置，不能和 NVIC 混为一谈。

UART/DMA ISR 只记录环形 DMA 的位置和接收时间。CRC、浮点解析、CRSF 通道解包留在主循环。1 ms SysTick 还会补记无 IDLE 的连续流位置，避免只靠空闲中断时漏掉时间信息。

两个 RX 缓冲各 1024 字节、64 个位置/时间事件；后台每次最多处理 128 字节并检查 500 us 预算。积压/事件溢出会清残帧并撤销当前目标；UART 错误由后台 Abort/检查 DMA 状态后重启，不在 ISR 内长时间轮询 HAL。

SysTick 还检查 200 ms 主机指令超时和 300 ms 遥控有效数据年龄。这样后台卡住时，软件超时仍可工作；但 SysTick 本身是低优先级，长时间关中断或更高优先级 ISR 卡死仍会影响它。

## 5. 20 ms 电机控制链

TIM13 的实际运行配置由 `Motor_ControlTimerStart20ms()` 设置为 PSC=8399、ARR=199，APB1 定时器时钟 84 MHz，周期 20 ms；不能只看 `tim.c` 里 CubeMX 初始化的旧计数参数。

控制中断先询问 `DriveControl_ControlTick()` 是否有就绪的唯一来源。就绪时一次提交四个轮目标并执行 PID；未就绪时清 PWM/PID，仍更新编码器测速和里程计，因此“待机轮子没有闭环保持力”是当前控制策略。

测速使用编码器计数差和 DWT 实际间隔：

```text
raw_cps = 本次编码器增量 / 实际 dt_s
filtered_cps = previous_cps + 0.35 × (raw_cps − previous_cps)
```

滤波状态用 float 保存，再四舍五入发布整数 cps；不在滤波每一步强行截成整数，避免静止残留约 ±2 cps。对外串口和对内 PID 单位不同：

```text
目标 cps = round(目标 rad/s × 1333 / (2π))
反馈 rad/s = 实际 cps × (2π) / 1333
轮缘速度 m/s = 轮角速度 rad/s × 0.04
```

因此 2 rad/s 约等于 424 cps，对应轮缘速度约 0.08 m/s；不能将 2 rad/s 当成 2 m/s。

四轮分别使用增量 PID：

```text
e[k] = target − feedback
Δu = Kp(e[k]−e[k−1]) + Ki·e[k] + Kd(e[k]−2e[k−1]+e[k−2])
u[k] = 限幅(u[k−1]+Δu, −10000, +10000)
```

默认表为 Kp=0、Ki=0.10、Kd=0，但有效 FRAM 参数会覆盖默认值。这里 Ki/Kd 是该离散实现的系数，不是随意照搬连续 PID 参数；改控制周期后需要重新审视整定。

## 6. 谁拥有电机控制权

`drive_control.c` 是正常运行中唯一的来源仲裁：CH6 选 HOST/REMOTE/STOP，CH5 为总解锁。手动目标在后台用快照计算，在控制中断中整体提交；上位机命令在非 HOST 模式即使 CRC 正确也只统计为忽略。

当前 HOST 授权使用 `RDK_UART_GrantFreshControl()`：清空下位机旧数据后接收新的合法帧，允许首帧为非零。没有按键模拟零速，也没有在收到随机串口字节时提前解锁。旧 `RDK_UART_SetControlEnabled(1)` 的严格零速策略仍为独立接口保留，但当前运行时仲裁不使用它。

上位机档位和 CH5 高位稳定后不要求重拨 CH5；手动模式仍需重新解锁和摇杆回中。失联锁定由单独的 `loss_rearm` 标志保持，防止恢复无线数据就自动起步。完整状态和操作见 [runtime_control.md](runtime_control.md)。

协议没有主机目标生成序号，所以“新收到的帧”不能证明“导航意图是新生成的”。下位机无法替上位机取消旧导航任务；切换档位就是允许执行它当前的速度输出。

## 7. 姿态、里程计和 ROS 分工

LSM6DSR 的陀螺仪提供旋转传播，加速度计提供重力方向，Mahony 比例/积分反馈修正可观测误差。开机先做静止零偏校准，姿态再使用 32 个新近静止加速度观测对准；短缺少加速度只暂停观测计数，长间隔或运动会重启对准。长陀螺仪断采也会使姿态重新初始化。

上传的是 **qx、qy、qz、qw**，陀螺仪单位 rad/s，加速度单位 m/s²且保留重力。三个数据组分别标记新鲜和有效，不能用一个四元数是否为零来猜测整帧有效。当前未融合磁力计，yaw 是相对航向，会有长期漂移，不能当作绝对罗盘方向。

`Odom.c` 会根据四轮计数进行本地积分，但当前 USART3 反馈**只发送轮速和 IMU，不发送本地 x/y/yaw 位姿**。RDK 端驱动据实际轮速计算和发布自己的里程计，是否融合、由哪个节点发布 TF，属于上位机配置。

slam_toolbox、激光数据处理、Nav2 的全局/局部规划与导航控制不运行在 F405 上。上位机应把底盘速度换算为四轮目标角速度后发 `0x03`；手动模式只替换驾驶来源，不停止轮速/IMU 反馈，因此建图节点仍可使用实际运动反馈。

## 8. 修改时的边界

避免在 ISR 添加 `printf`、OLED 整屏发送、SPI/I2C 轮询或长循环。新增目标来源应交给 `drive_control`，不要直接在主循环和 ISR 中分别写四轮 PWM。

现有 SPI、INA219、FRAM 异常路径仍有阻塞超时；HardFault/Error_Handler 和独立看门狗没有完整重构。主机模拟测试证明逻辑条件，不等于实板 CPU 占用率和最坏控制抖动已有测量结论。需要继续优化时，先做 DWT/GPIO 计时，再参考 [历史核查记录](history/followup_review.md)。
