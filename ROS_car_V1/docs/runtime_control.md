# 上位机 / 遥控运行时切换与建图

本版固件只需烧录一次，之后通过遥控器开关选择驾驶来源。`drive_control.c/.h` 统一控制四轮目标提交、PWM 使能和超时停车；主循环不再执行方形轨迹、角度测试、开环测试或语音导航驾驶分支。轮序、方向、PID、尺寸参数沿用现值。

## 遥控器设置

| 通道 | 设置与作用 |
|---|---|
| CH1 | 左右平移摇杆 |
| CH2 | 前后移动摇杆 |
| CH4 | 转向摇杆 |
| CH5 | 两段开关，总锁定/解锁：低位锁定，高位解锁 |
| CH6 | 模式开关：低位上位机，中位停车，高位手动遥控 |
| CH8 | 原来的报警灯/蜂鸣器，不作为停车开关 |

开关名称取决于遥控器混控设置，需要把实际拨杆分配到 CH5、CH6。两段 CH6 可使用低/高两个位置；三段开关额外提供中位停车。CRSF 原始值通常为低约 172、中约 992、高约 1811。本版按 CH6 ≤650 选上位机、≥1350 选遥控，其余范围停车，选择来源需要 3 个新的稳定快照；第一帧位置改变便先清 PWM。

## 日常切换

遥控建图切到导航：保持 CH5 高位，CH6 切到低位上位机。固件先停车，确认档位稳定后授权 RDK，丢弃下位机里积压和残留的串口数据，再接收新的合法速度指令；该指令可以直接为非零速度。不再要求 CH5 额外低后高，也不要求 RDK 补发零速握手，无需修改上位机代码。

上位机切回手动：CH5 拨低、摇杆回中，CH6 选高位遥控，等待档位稳定后把 CH5 拨高。手动模式仍需重解锁及连续 3 个新的回中采样；收到同一缓存快照的多次后台轮询不能累计解锁/回中计数。

CH5 低位始终锁定两种模式，CH6 中位始终停车。切换会清除目标、PID 累积输出及旧命令就绪状态。USART3 报文格式不变，不新增 ACK 或控制模式报文。

“新指令”指清掉下位机旧接收缓冲后新收到的帧。协议没有序号、控制来源或目标生成时间，因此下位机无法区分 RDK 新生成的导航目标与它持续重发的旧目标。切到上位机档即表示允许当前 RDK 输出接管；如果 RDK 正在发送非零速度，小车可能直接起步，单片机复位后也一样。可先取消不需要的旧导航目标，再切换模式。

OLED 开屏后进入 **STATUS** 页，第一行显示：

| 显示 | 含义 |
|---|---|
| CTRL:HOST | 上位机拥有控制权，已有未超时的有效命令 |
| CTRL:HOST WAIT | 已允许上位机接管，等待新速度帧；可以为非零 |
| CTRL:HOST LOCK | 已选上位机，CH5 尚未解锁或失联后的重解锁尚未完成 |
| CTRL:REMOTE | 手动遥控可驾驶 |
| CTRL:REMOTE LOCK | 已选遥控，等待 CH5 重解锁或摇杆回中 |
| CTRL:STOP | CH6 中位、过渡位置或切换确认中 |
| CTRL:LINK LOST | 用过遥控后，遥控数据失效/断流 |

## 无遥控器和失联行为

- 上电一直没有收到合法遥控数据：独立上位机方式，不用开遥控器，清掉启动积压后收到有效新速度帧即可驱动，不要求零速握手。
- 一旦收到过遥控数据：CH5 成为两种来源的总解锁。首次连接或单片机复位后，CH6 为上位机且 CH5 为高位，确认后可直接授权；CH5 为低位仍保持锁定。首次连接选手动且 CH5 已在高位，仍须先低后高及摇杆回中。
- 遥控数据年龄达到 300 ms，或 UART5 接收报错被标为无效：毫秒看门狗停止当前驱动，两种模式都受此限制；不会自动切到另一来源。恢复数据后仍须重新选定/解锁。
- 上位机控制时，RDK 超过 200 ms 无合法命令会清空目标/PID、关闭 PWM。权限仍有效时，下一个合法新速度帧可恢复驱动，无需零速。CRC 错误、NaN/Inf、超范围和过期帧不刷新超时。USART3 接收错误恢复后也等待新有效帧；手动模式下，上位机命令超时或 USART3 报错不会切断手动控制。
- 这里检测的是有效 CRSF 通道帧的年龄。接收机若在射频失联后持续输出旧通道值，串口超时不能判断射频断链；应配置接收机失联时输出 CH5 锁定，并实测遥控器断电后的行为。

关闭 PWM 不代表机械上瞬间制动，车辆仍可能惯性滑行。SysTick 的软件超时受更高优先级 ISR/关中断影响，故障死循环/独立看门狗等历史未处理项仍见核查报告。

## 遥控建图

主循环始终处理轮速/IMU 反馈，并以约 50 Hz 经 USART3 上传。手动模式仅忽略上位机的电机目标，不停用底盘反馈，因此上位机可继续运行底盘驱动、里程计、雷达与建图节点。串口测试工具应退出，同一串口由底盘驱动使用。

手动平移指令上限为 1000 cps、转向混合量上限 500 cps，混合后再限制每轮不超过 1000 cps。按当前每圈 1333 计数、轮半径 0.04 m 换算，纯直行约 0.19 m/s。上述上限是建图初始配置，未在实板测定极限速度。

## 验证

运行时控制测试直接编译实际 ELRS、RDK、DMA、麦轮换算和控制仲裁源文件，通过 CRSF 和协议字节帧模拟外设，覆盖：

- 无遥控器的非零指令启动；独立进程模拟遥控器在线且 CH5 高/低位的上位机启动及复位；手动启动仍需重解锁。
- 单来源目标提交、手动限速、手动期间上位机命令/接收错误隔离、遥控时反馈继续发送。
- CH5 高位直接从手动切上位机、首帧清 PWM、稳定确认、新非零帧接管、重复授权不丢活跃命令、旧 RDK 队列/残帧/未报 IDLE 字节丢弃；手动重解锁与回中。
- 无后台处理时 300 ms 遥控数据超时、失联锁定、恢复不自动起步、上位机 200 ms 超时、CH5 总锁定。
- CH6 中位停车、混合轮速限制、UART5 错误在下一看门狗节拍触发停车。
- RDK 超时和接收错误后直接用新非零帧恢复；CRC、NaN、范围、过期检查保留；旧 RDK 严格授权 API 的零速握手兼容性。

`tests/rdk_uart/run_runtime_control_tests.ps1` 可独立运行，不需要桌面上的上位机协议文件：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests/rdk_uart/run_runtime_control_tests.ps1 -Configuration Debug
powershell -NoProfile -ExecutionPolicy Bypass -File tests/rdk_uart/run_runtime_control_tests.ps1 -Configuration Release
```

完整测试入口仍为 `tests/rdk_uart/run_tests.ps1`，其中旧协议互通测试需要指定原始 `x5car_protocol.cpp/.hpp` 所在目录。本次接管修改通过上述独立 Debug/Release 测试及 CMake Debug/Release 固件构建；未运行缺少原上位机文件的完整测试。Keil 构建和实板拨杆操作尚未验证，用 F8 烧录后检查实际通道值及断电失联行为。
