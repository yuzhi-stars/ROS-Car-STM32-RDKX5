# 首次联调：从烧录到遥控建图和导航

按“运行固件 → 读反馈 → 查控制权 → 校验轮速 → 手动建图 → 上位机导航”的顺序推进，每一步都有明确观察结果。

## 1. 烧录和上电

按 [硬件表](02_hardware.md) 确认时钟、SWD、电源和 RDK 串口。首次电机联调可让轮子离地，RDK 暂停发送运动目标，CH5 锁定。新固件复位后允许直接接收有效的非零上位机目标，不会替上位机取消旧导航。

执行 `Build Debug`，再执行 `Flash DAPLink OpenOCD` 或已绑定的 F8。检查 OpenOCD 编程、校验、复位并正常退出；若按了 F5，确认没有停在 main 或其他断点。

正常上电时：

- 约前 3 秒为 IMU 校准尝试，保持小车静止。
- OLED 默认熄屏，按 PC2 对应旋钮按键开启，转旋钮选页面。
- 进入后台后，用户 LED 每 500 ms 翻转，蜂鸣器有启动节奏。
- USART3 开始反馈，正常约 50 Hz，不需要先收到上位机速度命令。

如果一点状态都没有，先检查断点和 `Error_Handler()`，再检查 HSE/LSE 电路。OLED 黑屏不能单独说明程序没运行。

## 2. 先验证串口

USART3 为 115200 8N1，TX/RX 交叉、共地。数据为二进制，普通终端显示乱码不代表异常。

| 帧头/类型 | 长度 | 内容 |
|---|---:|---|
| `AA 55 90` | 22 字节 | FL/FR/RL/RR 实际轮角速度、有效标志、CRC |
| `AA 55 91` | 46 字节 | qx/qy/qz/qw、gyro、accel、有效标志、CRC |

约 50 Hz 时每秒 3400 个数据字节；按 8N1 约占 115200 线速的 29.5%，不等于占满串口。实际频率还受后台调度和外设错误影响。

确认持续同步、CRC 正确、手推某轮时对应轮速变化。当前反馈没有控制权 ACK，收到 IMU 不代表电机有权限。测试工具和底盘驱动不能同时占同一串口；切换程序前释放设备。

## 3. 检查 IMU

进入 OLED `IMU DIAG`：

| 状态 | 检查项 |
|---|---|
| WAIT CAL | 零偏未通过；静置，查看 WHY、N/R、新采样年龄 |
| ALIGN | 已校准，正在积累 32 个新的合格观测 |
| READY | 当前姿态有效 |
| STALE | 姿态/采样过期，检查 SPI、新数据位和采样间隔 |

flags 按位解释：`0x01` 姿态、`0x02` 陀螺仪、`0x04` 加速度。`0x06` 是 gyro/accel 有效但姿态无效，不能理解为整包损坏；主机可能把无效姿态显示为 NaN。静止加速度模长接近重力加速度，不是 0。

六轴融合的 yaw 是相对航向，可能长期漂移。改变 IMU 安装方向要做坐标变换，单改 ROS frame 名称不会旋转数据轴。

## 4. 核对闭环和单位

协议目标是 rad/s，PID/菜单轮速主要为 cps。按现值 2 rad/s 约 424 cps、轮缘速度约 0.08 m/s，不能当成 2 m/s。对外轮序固定为 FL/FR/RL/RR。

先手推轮子确认对应反馈，再用小目标观察目标/反馈是否同号、实际轮速是否跟随。反馈反号应按真实接线修正 `motor_config[]`，不能靠提高 PID 增益掩盖。当前原车轮序已确认，移植新接线时再核对。

默认 Kp=0、Ki=0.10、Kd=0，但 FRAM 有效参数会覆盖默认值，以菜单实际值为准。没有有效驾驶命令时只采样编码器，不运行驱动 PID；零 PWM 不承诺机械立即刹停或零速保持力。

## 5. 遥控建图

在遥控器通道监视器确认开关确实分配给 CH5、CH6。低/高是通道输出值，物理上下位置由混控和反向决定。

| 通道 | 用途 |
|---|---|
| CH1 | 左右平移 |
| CH2 | 前后 |
| CH4 | 转向 |
| CH5 | 低位锁定、高位允许驱动 |
| CH6 | 低位上位机、中位停车、高位手动 |
| CH8 | 灯/蜂鸣器报警，不是停车开关 |

手动进入：CH5 低位 → 摇杆回中 → CH6 高位并等待稳定 → CH5 高位。STATUS 显示 `CTRL:REMOTE` 才驾驶；`REMOTE LOCK` 时检查是否经过低位、摇杆是否回中、通道是否接对。

RDK 运行底盘驱动、雷达和 slam_toolbox。手动时实际轮速/IMU 仍上传，上位机继续处理里程计和激光；主机下发的速度此时被忽略。建图结束按你已有的上位机流程保存地图。

本资料未附 RDK 的 ROS 发行版、雷达型号、包名和 launch 文件，不能将任意网上的启动命令当成本车可直接运行的命令。

## 6. 切到导航

1. 在 RDK 取消不需要的旧导航目标，确认准备执行的任务。
2. 保持 CH5 高位，将 CH6 切到低位上位机。
3. 固件先停车、稳定确认并清旧串口积压，再接管新帧；无需重拨 CH5 或主机零速握手。
4. `CTRL:HOST WAIT` 表示已授权、等新速度帧；`CTRL:HOST` 表示收到未超时的有效帧。
5. 使用现有 Nav2 流程定位和发送目标。

遥控器在线、CH6 上位机/CH5 高位时复位，也能确认后接管，不必先关遥控器再整车断电。回手动仍按 CH5 低位 → 回中 → CH6 高位稳定 → CH5 高位。

## 7. 按层次排查

| 现象 | 优先核查 |
|---|---|
| 完全无反馈 | main 断点、启动校准、USART3 参数、TX/RX/地、设备节点和占用 |
| 有反馈但不动 | 看控制权状态，反馈与驱动授权是两回事 |
| `HOST LOCK` | CH5 是否高位；此前失联是否需低后高解锁 |
| `HOST WAIT` | 是否真的收到新 `0x03` 帧，CRC/数值是否正确，ROS 指令是否经过底盘驱动转发 |
| `STOP` | CH6 中位/阈值区、档位是否稳定 |
| `LINK LOST` | CRSF 接收、UART5 错误和通道帧年龄，恢复后重解锁 |
| 间歇停车 | 主机有效速度帧间隔是否达到 200 ms，错误帧不续命 |
| 关遥控器后导航也停 | 用过遥控后，两种模式都受无线数据失联保护，这是现有策略 |
| 射频失联却没停 | 接收机可能继续发旧通道；配置 failsafe 输出 CH5 锁定并上板验收 |
| 姿态一直 NaN | 看 flags；06 时检查校准、对准、采样年龄和安装方向 |
| 单轮异常 | 反馈符号、PWM 接线、有效 FRAM PID、计数/量纲 |

调试器可读取 `RDK_UART_GetStatistics()`：`commands_while_disabled` 为无授权帧数，`crc_errors` 为 CRC 错误，`invalid_commands` 为非法数值，`stale_commands` 为过期命令，`command_timeouts` 为超时次数。它们不通过当前 USART3 自动上传，不要在二进制口混入 printf。

## 8. 上位机边界

硬件闭环正确后再检查速度订阅、轮速到里程计换算、激光、TF 和导航配置。可用 `ros2 topic list` 查看实际话题，再用 `ros2 topic info <实际速度话题> -v` 查发布/订阅；未经确认不要假定当前驱动的话题名或 Twist/TwistStamped 类型。

F405 不运行 slam_toolbox/Nav2、不直接发布 ROS 消息。这里“RDK”是上位机板卡名称，这条底盘串口与卫星 RTK 无关。
