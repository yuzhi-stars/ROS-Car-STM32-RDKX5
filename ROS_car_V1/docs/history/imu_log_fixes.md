# 上位机日志问题修复与验收

> 历史过程记录。当前编译烧录与控制行为以[文档索引](../README.md)和[运行时控制说明](../runtime_control.md)为准。

用户反馈：50 Hz 接收轮速与 IMU、CRC/丢弃字节为零，2 rad/s 指令下四轮反馈接近目标；整个测试中 IMU flags=06、四元数为 NaN，静止轮速约 0.009 rad/s。用户已确认轮序正确，本次沿用轮序、接线方向与尺寸参数。

## 实现

1. `imu_attitude.c` 初始化不再因一次空加速度立即清零。短缺失暂停计数；仍需要 32 个新的合格观测，间隔超过 30 ms、运动或非法输入会重置窗口。陀螺仪超过 50 ms 断采仍重新对准。
2. `imu_calibration.c/.h` 维护可重试的静止窗口：至少 200 个新陀螺仪样本、至少 2 秒、0.95～1.05 g、各轴原始值不超过 ±600 LSB、标准差不超过 50 LSB。陀螺仪和加速度无需在同一次读取中同时置新数据位；仅以 30 ms 内的新加速度检查资格。
3. 启动仍有约 3 秒校准尝试。未完成时由后台继续工作，四轮目标必须为零、测得速度须在 ±10 cps 内。拒绝窗口后退避 250 ms；后台不执行 HAL_Delay，不阻塞串口收发。成功后锁定零偏，不在行驶中持续重校准。
4. `Motor.c` 轮速低通使用浮点状态，保留原来的 alpha=0.35，再四舍五入输出整数 cps；去掉输入处不必要的整数截断。停止时会收敛到零，避免原先整数除法停在 ±2 cps（约 ±0.00943 rad/s）。控制周期和 PID 系数沿用现值。
5. OLED 主页新增 `IMU DIAG`，10 Hz 更新。保持上电熄屏、按键开启、DMA 分片刷新。诊断 API 和显示不会给 USART3 添加文本或更改帧布局。
6. RDK 待发有效位按新数据组累计，直到一次 UART 发送成功后消耗。两个传感器分时到达时，后来的新组不会擦除先前已经采到、尚未发送的组。姿态融合仍只用本次新陀螺仪，旧加速度不会重复用于对准；只来新加速度时，可以读取仍在 50 ms 内的上一份姿态，但不会凭空生成新四元数或重复标记已发姿态。

## OLED 诊断字段

按旋钮开屏，旋转到 `IMU DIAG` 并按下；再次按下返回。

| 字段 | 含义 |
|---|---|
| IMU:WAIT CAL | 尚未取得合格的陀螺仪零偏 |
| IMU:ALIGN | 已有零偏，正在对准姿态 |
| IMU:READY | 最近估计有效 |
| IMU:STALE | 曾完成对准，当前没有有效的新估计 |
| CAL:OK / WAIT STILL | 零偏已确认 / 等待静止窗口 |
| WHY | 最近一次拒绝原因，成功后为 OK；收集中保留上次原因 |
| CAL N / R | 当前候选窗口新陀螺仪样本数 / 被丢弃的非空窗口数 |
| ALIGN n/32 / R | 对准进度 / RDK 检测到对准计数下降的次数 |
| AGE G / A | 最近陀螺仪/加速度数据年龄，单位 ms |
| GAP / MAX | 超过 50 ms 触发的陀螺仪断采重置数 / 观察到的最长新陀螺仪间隔（ms） |

`WHY:WHEELS MOVE` 也可能是目标非零但实际车轮尚未转动，表示不满足后台校准许可；`GYRO MOVING` 指原始值超限，也可能来自器件异常/过大零偏，不能单凭该文本确认机械运动。`NO SENSOR` 表示启动 IMU 初始化未成功，本次没有增加运动传感器初始化失败后的重启流程。

## 软件验证

- 原来每 25 次丢一次加速度、运行数百次仍不能对准的复现用例，现在能完成 32 个新观测的对准。
- 独立/交错的 gyro-ready 和 accel-ready、启动运动与高噪声窗口失败后恢复、行驶许可阻止校准、过期加速度、长陀螺仪断采、NaN/自由落体、HAL tick 回绕。
- 实际校准模块 → 设置 RDK 零偏 → Mahony → 实际发送缓冲 → 原上位机解析器，检查 06→07、四元数有效性和诊断计数。
- 轮速滤波的正/负零尾收敛、独立计算的 0.35 阶跃响应和小数状态；菜单的开屏、旋钮进入诊断页、等待/对准/就绪/失效状态和 10 Hz 刷新。
- 保留串口 CRC、命令锁定、200 ms 超时、DMA 恢复、OLED、ELRS、里程计及 HAL I2C 回归测试。

编译与测试命令沿用 `docs/realtime_optimization.md`。本次尚未烧录或实板复测，不能由模拟测试推断日志中的实际硬件根因已完全消除。

## 烧录后复测

1. 使用 F8 烧录后，上电静止约 5 秒；若刚启动过运动测试，先持续发零速并使车轮停止，让后台完成静止窗口。
2. OLED 诊断应从 WAIT CAL/ALIGN 到 READY；正常新三组数据齐全时，上位机应看到 `imu_ok=1 flags=7`、有限且模长接近 1 的四元数。gyro-only 的新采样仍可能短暂出现 flags=3，不能要求每一帧都固定为 7。
3. 用原来的 2 rad/s 测试确认轮速跟踪没有退化，结束后观察轮速逐步返回 0；真实微小运动/编码器噪声仍可能产生非零读数。
4. 若仍长期 flags=6，记录 IMU DIAG 的校准原因、N/R、ALIGN 和 GAP/MAX，可区分未校准、反复对准与断采；不要通过强行置有效位掩盖问题。
5. 保持原有先发零速解锁、连续发送速度和 200 ms 超时切断 PWM 的行为。主动发送零速停车与停止发指令的超时停车需要分别验证。
